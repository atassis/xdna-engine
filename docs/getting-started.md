# Getting started

xdna-engine is a Rust service that runs ASR, embeddings, diarization, and small LLMs on
the AMD XDNA2 NPU. This page covers building it, installing it as a user service, and
running your first request.

## Prerequisites

- **Hardware**: an AMD XDNA2 NPU (Ryzen AI 9 465 / Krackan is what this is developed
  against), Linux, the `amdxdna` kernel driver loaded, and `/dev/accel/accel0` present.
- **Rust** -- `cargo` on `PATH`.
- **XRT headers and libs** for the `amdxdna` driver -- `xrt/xrt_bo.h` under `XRT_INC_DIR`
  (default `/usr/include`) and `libxrt_coreutil.so*` under `XRT_LIB_DIR` (default
  `/usr/lib`).
- **An `onnx-asr` venv** with `onnx_asr` importable. `install.sh` copies
  `libonnxruntime.so.*` out of it for the service to link against. Point at yours with
  `ONNX_ASR_VENV=/path/to/venv`; unset, it tries `./.venv`, then
  `~/.local/share/xdna-engine/onnx-asr-venv`, in that order.
- **Model artifacts** under `artifacts/` -- weights, ONNX graphs, and prebuilt xclbins.
  These are generated by the export scripts in `scripts/` (see "Model artifacts" below).

All of these are checked by `install.sh`'s preflight before anything is built, and it
fails loud (naming the missing thing) rather than installing something broken.

## Build and install

```
ONNX_ASR_VENV=/path/to/venv ./install.sh
```

Run this from the repo root, not `scripts/install.sh` (that path is a deprecated shim
that forwards to the same script). It is idempotent and safe to re-run after every
`git pull`. What it does:

1. Preflights `cargo`, the onnx-asr venv, and XRT headers/libs.
2. Runs `cargo build --release` for the Rust workspace.
3. Installs the built `npu` binary to `~/.local/bin/npu`.
4. Publishes the AIE kernels the config's scenarios need into a stable production root
   (`~/.local/share/xdna-engine` by default), and hardens `libonnxruntime.so` into a
   stable dir so the service survives a `cargo clean`.
5. Preflights `~/.config/npu/engine.toml`: every scenario it references must resolve to
   weights on disk, or the install refuses. If you have no config yet, see
   [configuration.md](configuration.md) for a worked example.
6. Writes a systemd `--user` unit at `~/.config/systemd/user/xdna-engine.service` and
   retires any older `npu-asr.service` / `npu-serve.service` units.

It **does not start anything and does not touch the NPU** -- the device is
single-tenant and may already be in use, so the script only prints the commands to
start the service.

`MODEL=gigaam ./install.sh` selects the GigaAM (Russian-only) artifact set instead of
the default Parakeet (multilingual) one; this only affects which artifacts the preflight
checks for, not what the running service serves (that comes from `engine.toml`).

## First run

Start the service:

```
systemctl --user start xdna-engine.service
```

Or run it in the foreground for a quick check:

```
npu serve
```

Then, from another shell:

```
npu transcribe audio.wav        # one-shot ASR, prints the transcript
npu embed "some text"           # one-shot embedding
npu models                      # what this install is configured to serve
```

`npu transcribe`/`npu embed`/`npu generate`/`npu chat`/`npu diarize` each load the model
they need in-process and exit -- they do not require the service to be running. `npu
serve` is the one process that owns the NPU continuously and answers HTTP requests.

Every generation prints a one-line measurement to stderr (tokens/s, ms/token, the latency
tail, and which layer the time actually went to). `npu generate --stats` prints the full
breakdown instead. `--output json` streams the whole thing as NDJSON on stdout -- one line
per token, carrying that token's own timing -- so `> run.jsonl` gives you a file `npu
stats` and `npu replay` read back. See [measurement.md](measurement.md).

`npu top` is the live view of the device: who is resident, what is serving right now,
how much device memory each model holds, and what share of the service's uptime each one
has occupied the NPU for. It reads the status file the service publishes, so it never
touches the device and cannot hang on a busy one.

## What success looks like

With the service running:

```
curl http://127.0.0.1:11434/healthz
# {"ok":true,"npu":true,"loaded":1,"failed":[]}

curl http://127.0.0.1:11434/v1/models
```

`scripts/test_install.sh` automates this: it waits for `/healthz`, prints `/v1/models`,
and posts a real clip to `/v1/audio/transcriptions`, checking the response has a
non-empty `text` field.

The OpenAI-compatible routes are the ones a normal client speaks: `POST
/v1/audio/transcriptions` (multipart WAV -> `{"text": ...}`), `POST /v1/embeddings`,
`POST /v1/chat/completions`, `POST /v1/completions`, `POST /v1/audio/diarizations`.

## Model artifacts

`artifacts/` is not checked into the repo -- it holds weights and xclbins, which are
either exported from Hugging Face checkpoints or built by the AIE toolchain. The
scripts that produce them live in `scripts/`; `scripts/README.md` groups them by job
("Model export and conversion", "Kernel builds"). `scripts/fetch_models.sh` downloads
the upstream checkpoints into the Hugging Face hub cache; the per-model
`extract_*_encoder.py` / `convert_*.py` scripts turn those into the layout each scenario
expects.

Weight checkpoints for models on the declarative `npu-weights` path (see
[configuration.md](configuration.md)) can also be baked on demand:

```
npu bake <model-name>          # bake the checkpoint a configured model's scenario declares
npu weights bake --source hf:facebook/opt-125m --arch opt
```

## Building the AIE kernels

The engine runs against prebuilt xclbins in `artifacts/` and does not need the AIE
toolchain for normal use. Building the kernels themselves is a separate path with its
own pinned toolchain (`toolchain.lock`, brought up by `scripts/toolchain_up.sh` and
gated by `scripts/toolchain_smoke.sh`) -- only needed if you are changing a kernel or
building artifacts for a model that has none yet.

## Uninstall

```
scripts/uninstall.sh
```

Stops and removes the systemd unit and the `npu` binary. It keeps `~/.config/npu/engine.toml`,
the onnxruntime lib, and `artifacts/` -- remove those by hand for a full wipe.
